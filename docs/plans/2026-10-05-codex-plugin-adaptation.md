# Адаптация плагина Citeck для Claude Code и Codex

## Цель и статус

Сделать существующий плагин Citeck универсальным для локальных Claude Code и Codex. Репозиторий `Citeck/citeck-claude-code-tools`, имя плагина `citeck` и расположение `plugins/citeck/` сохраняются. Пользователь подтвердил сохранение одного репозитория; этот документ описывает предлагаемые этапы реализации.

Статус: реализация упаковки и общих инструкций выполнена; автоматические проверки и API localhost пройдены. Полная приёмка клиентов и UI пока не завершена.

Номер следующего выпуска по поручению пользователя: `3.12.0-SNAPSHOT`. Версия Python-проекта остаётся `3.0.0`.

Исходное состояние на 2026-10-05:

- `master` совпадает с `origin/master` после `git pull --ff-only`.
- Исходный commit: `dff000d` (`ReadME.md update`).
- Версия плагина: `3.11.1`; версия Python-проекта в `pyproject.toml`: `3.0.0`. Это разные текущие значения; в этой работе не выравнивать их без проверки назначения версий.
- Установленный Codex CLI: `0.160.0`. Проверена справка `codex plugin` и `codex plugin add`; установка плагина пока не проверена.
- В рабочей копии есть пользовательское изменение `.gitignore`. Сохранить его и не включать в изменения адаптации.
- Проверены исходники и официальная документация; тесты, авторизация и доступ к стендам в рамках анализа не выполнялись.

## Архитектурные решения

1. Один MCP-сервер, один набор библиотек `lib/`, скриптов, шаблонов и справочных материалов. Не создавать отдельный проект и не копировать Python-реализацию для Codex.
2. Сохранить `.claude-plugin/plugin.json`, корневой каталог Claude и рабочую установку Claude Code.
3. Для первого выпуска добавить `.codex-plugin/plugin.json` и каталог `.agents/plugins/marketplace.json`. Поддерживаемый формат совместимости Codex позволяет проверить перенос с минимальными изменениями текущей упаковки. Переход на переносимый корневой `plugin.json` не является условием этого выпуска.
4. Все пять навыков должны использовать общие `SKILL.md`. Убрать обязательную зависимость от инструментов и переменных Claude; необходимые различия описать короткими инструкциями для клиента. Не поддерживать две вручную редактируемые копии одного процесса.
5. Конфигурации запуска MCP могут различаться между клиентами, если это требуется для разрешения путей. Они запускают один и тот же сервер. Не предполагать совместимость переменных без проверки установки.
6. Сохранить текущие API инструментов и формат `~/.citeck/`. Авторизация в Citeck остаётся ответственностью существующих библиотек; `codex mcp login` не заменяет этот процесс для локального сервера.
7. Поддерживаемые среды первого выпуска: локальный Codex CLI и локальный Claude Code. Codex в настольном приложении и IDE проверять отдельно при доступности; не объявлять их проверенными по результатам CLI.
8. Удалённое выполнение, Codex Cloud, публичный HTTP MCP-сервис и публикация в публичном каталоге OpenAI не входят в эту работу. Для них отдельно потребуются доступ к сети, доставка секретов и иной способ получения OAuth callback.

## Найденные зависимости от Claude

| Расположение | Зависимость | Решение |
|---|---|---|
| `plugins/citeck/.mcp.json` | `${CLAUDE_PLUGIN_ROOT}` в аргументах `uv` | Проверить фактическое разрешение пути Codex; при необходимости добавить конфигурацию запуска для Codex |
| Все пять `SKILL.md` | `allowed-tools`, имена инструментов, ссылки на вызов навыков Claude | Использовать общие инструкции; разрешения настраивать средствами каждого клиента |
| Два навыка создания описания задачи | `context: fork`, подстановка команд через `!` и обратные кавычки | Явно выполнять git-команды; не обещать автоматический отдельный контекст |
| Навыки авторизации, создания задач и тестирования | `${CLAUDE_SKILL_DIR}` | Разрешать пути от фактического расположения прочитанного `SKILL.md` |
| `skills/_shared/task-description-guide.md` | `AskUserQuestion` | Описывать вопрос пользователю без обязательного имени инструмента |
| `citeck-test-feature`, его справочники и шаблоны | `mcp__plugin_playwright_playwright__*`, `Agent`, настройки `.claude/settings.local.json` | Выбирать доступный браузерный инструмент и механизм делегирования; предусмотреть последовательное выполнение |
| `servers/citeck_mcp.py` | Указания использовать `Read` для изображений и `/citeck:citeck-auth` | Описать просмотр изображений и настройку авторизации независимо от клиента |

Дополнительно: текущий навык создания задачи использует `assignee: "me"` и не запрашивает целевой выпуск. Общий навык должен учитывать инструкции текущего пользователя и запрашивать недостающие параметры. Значение `anton.ivanov` относится к личным настройкам автора этого плана; не закреплять его как исполнителя по умолчанию для всех пользователей плагина. Если исполнитель не определён запросом или применимыми пользовательскими инструкциями, запросить его явно. Существующий API сервера менять только при подтверждённой необходимости.

## Приёмочные сценарии

Каждый сценарий проверяется в Claude Code и Codex CLI. Для конкретного клиента записать версию, результат и ограничения. Подменённые ответы API подтверждают обработку ветвей, но не заменяют проверки клиента и согласованного стенда.

| Сценарий | Критерий приёмки |
|---|---|
| Установка и обновление | Загружаются пять навыков и один Citeck MCP-сервер; установленный пакет работает независимо от исходного каталога |
| Запуск сервера | Инициализация и `ping` проходят; сбой запуска даёт понятную причину; пути с пробелами работают |
| Профили | Существующие профили читаются; фактический URL виден; запросы трекера, документации и Records попадают в назначенные среды |
| Документация | Русский запрос возвращает обоснованный ответ с источниками; пустой результат, ошибка авторизации и отсутствие RAG обработаны |
| Создание задачи | Выпуск и исполнитель переданы; предпросмотр соответствует создаваемой задаче; отмена не создаёт запись; после правки показан новый предпросмотр |
| Выбор исполнителя | Явно заданный исполнитель и настройки другого пользователя соблюдаются; при отсутствии значения навык задаёт вопрос; личное значение `anton.ivanov` не становится общим значением по умолчанию |
| Смена среды после предпросмотра | Смена `ept_profile` или `active_profile` другой сессией не меняет явно переданный профиль создания. При изменении URL выбранного профиля требуется новый предпросмотр и подтверждение; при удалении профиля задача не создаётся и переход на другую среду не происходит |
| Описание в task.md | Использована правильная база diff; общий справочник найден в пакете; файл содержит согласованный формат и русский текст |
| Авторизация | PKCE завершает вход; тайм-аут/отмена объяснены; истёкшая сессия восстанавливается и исходная операция повторяется |
| Вложения | Комментарии и изображения загружаются; клиент действительно просматривает изображение по возвращённому пути |
| Records API | Чтение, разрешённая запись в локальную тестовую область, ошибка доступа и неверные параметры дают ожидаемый результат |
| План тестирования | Генерация, повторное открытие и проверка плана проходят; существующие пользовательские файлы не перезаписаны |
| Проверка UI | Завершён пользовательский сценарий; проверены конечное состояние, ошибки консоли и сетевые сбои |
| Делегирование | Доступные агенты соблюдают блокировки; при их отсутствии случаи выполняются последовательно с теми же критериями результата |
| Сохранение совместимости | Установка Claude и все существующие сценарии работают после изменения общих инструкций |

Реальное создание задачи в трекере и любые стендовые записи выполнять только при соответствующей авторизации. При её отсутствии проверить предпросмотр и обработку создания с подменой API, а реальную запись оставить явно непроверенной. Не считать такой результат полной проверкой выпуска.

## Ограничения и контроль изменений

- Сочетание конфигурации Codex и переменных путей должно быть подтверждено этапом 1. Документация переменных hooks не доказывает поддержку тех же подстановок в MCP.
