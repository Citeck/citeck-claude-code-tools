# Records API for server scripts

The `Records` object of server scripts (BPMN script task, gateway condition, computed attribute and role).

⚠️ In a BPMN process (script task, gateway condition) `Records` is the process engine's object with exactly TWO methods:
`Records.get(ref)` and `Records.query(query, attributes)`. There is NO `Records.queryOne` there — a call stops the process
with an error. Always pass the attributes to `Records.query` in a process; for one record use `page: {maxItems: 1}` and
read `result.records[0]` (it may be absent). `Records.queryOne` exists only in computed attribute and role scripts.

## Read, create and change a record

The scalar after `?` in an attribute read (`record.load("…")`, `document.load("…")`, the attributes of `Records.query`)
is one of: `?str`, `?disp`, `?num`, `?bool`, `?json`, `?id`, `?localId`, `?assoc`, `?raw`, `?bin`, `?appName`,
`?localSrcId` — no other exists. There is NO `?date`: a date or a date-time is read as ISO-8601 text with `?str`
(`"dueDate?str"` → `"2026-10-16T00:00:00Z"`, `new Date(value)` parses it). An unknown scalar fails the read silently —
the value is null. Without a scalar the display value (`?disp`) is read.

```javascript
// Records.get(recordRef) - get existing record
var record = Records.get("emodel/person@admin");
var name = record.load("name?str");

// Create new record (empty ID after @) - ONLY in BPMN Script Task!
var newRecord = Records.get("emodel/type@");
newRecord.att("name", "New Record");
var saved = newRecord.save();
var newRef = saved.getRef();

// IMPORTANT: NEVER chain Records.get(ref).att(...).save() in a single expression!
// .att() and .save() must be called on a record variable, NOT chained off Records.get().
// WRONG: Records.get(ref).att("field", value).save();
// RIGHT: var rec = Records.get(ref); rec.att("field", value); rec.save();
```

## Search: Records.query

The FIRST argument is the query object (it becomes the platform's `RecordsQuery`). It MUST say where to search:
- `ecosType: "<data type id>"` — the records of a data type: the type's id WITHOUT `emodel/type@`, e.g.
  `ecosType: "deal"`; in a workspace the id with its workspace prefix, e.g. `ecosType: "my-ws:deal"`. The platform
  resolves the type's records source itself — prefer it for records of a data type: the source id of a type is
  generated by the platform and differs from the type id. NEVER the full ref (`ecosType: "emodel/type@deal"`): the
  platform then filters by the type `emodel/type@emodel/type@deal`, which does not exist, and finds NOTHING — without an
  error.
- `sourceId: "<app>/<source>"` — a known source, e.g. `sourceId: "emodel/person"`, `sourceId: "emodel/comment"`.

A query with neither `sourceId` nor `ecosType` searches nowhere. There is NO `type` field in a query — the type goes into
`ecosType`, or into the predicate as `{"t": "eq", "att": "_type", "val": "emodel/type@deal"}` next to a `sourceId`.
Other fields: `language: "predicate"` with the predicate in `query`, `page: {maxItems: N}`,
`sortBy: [{attribute: "_created", ascending: false}]`, `consistency`.

The SECOND argument lists what to read of each record: a map `alias → attribute` (`{amount: "amount?num"}`), a list of
attributes or one attribute string. The value is an ATTRIBUTE with its scalar — `"?str"` alone reads the record
itself, not a field: write `stageDeadline: "stageDeadline?str"`, never `stageDeadline: "?str"`.

What the calls return:
- `Records.query(query, attributes)` returns an OBJECT `{records, totalCount, hasMore, messages}`, never an array.
  `records` is the array: each item is a map of the requested aliases plus `id` (the record ref). Iterate
  `result.records` — `result.length`, `result[i]`, `for (… of result)` see the object and do nothing.
- `Records.query(query)` without attributes (NOT in a BPMN process) returns the same object; its `records` is an array
  of record refs (strings).
- `Records.queryOne(query, attributes)` (computed attribute and role scripts ONLY, never in a BPMN process) returns ONE
  map (aliases plus `id`) or `null`; with a single attribute (a string) it returns that attribute's value.

```javascript
// Records of a data type, with a predicate
var result = Records.query({
    ecosType: "deal",
    language: "predicate",
    consistency: "EVENTUAL",
    page: { maxItems: 100 },
    sortBy: [{ attribute: "_created", ascending: false }],
    query: {
        "t": "and",
        "val": [
            { "t": "eq", "att": "_status", "val": "negotiation" },
            { "t": "not-empty", "att": "amount" }
        ]
    }
}, {
    name: "name?str",
    amount: "amount?num"
});

for (var i = 0; i < result.records.length; i++) {
    var deal = result.records[i];   // { name: ..., amount: ..., id: "emodel/...@..." }
}

// A known source
var comments = Records.query({
    sourceId: "emodel/comment",
    language: "predicate",
    query: { "t": "eq", "att": "record", "val": "emodel/doc@123" }
}, { text: "text", created: "_created" });

if (comments.records.length > 0) {
    var first = comments.records[0];
}

// One record or none — the same call in a BPMN process
var found = Records.query({
    sourceId: "emodel/person",
    language: "predicate",
    page: { maxItems: 1 },
    query: { "t": "eq", "att": "email", "val": "manager@example.com" }
}, { login: "?localId" });
var manager = found.records.length > 0 ? found.records[0] : null;
```

## Predicate types for Records.query

| Type       | Description            | Example                                              |
|------------|------------------------|------------------------------------------------------|
| eq         | Equals                 | {"t": "eq", "att": "status", "val": "active"}       |
| not-eq     | Not equals             | {"t": "not-eq", "att": "field", "val": null}        |
| gt / ge    | Greater / Greater-equal| {"t": "ge", "att": "version", "val": 1}             |
| lt / le    | Less / Less-equal      | {"t": "lt", "att": "priority", "val": 5}            |
| in         | In list                | {"t": "in", "att": "type", "val": ["a", "b"]}       |
| contains   | Contains substring     | {"t": "contains", "att": "name", "val": "test"}     |
| starts     | Starts with            | {"t": "starts", "att": "title", "val": "prefix"}    |
| ends       | Ends with              | {"t": "ends", "att": "title", "val": "suffix"}      |
| like       | Pattern (% = any chars)| {"t": "like", "att": "name", "val": "%test%"}       |
| empty      | Empty value            | {"t": "empty", "att": "client"}                     |
| not-empty  | Not empty              | {"t": "not-empty", "att": "client"}                 |
| not        | Negation               | {"t": "not", "val": {"t": "empty", "att": "field"}} |
| and / or   | Logical operators      | {"t": "and", "val": [...]}                          |

TIP: Add "not-" prefix for negation: not-eq, not-empty, not-contains

Date predicates:
| Syntax        | Description              | Example                                              |
|---------------|--------------------------|------------------------------------------------------|
| $NOW          | Current datetime         | {"t": "ge", "att": "_created", "val": "$NOW"}       |
| $TODAY        | Current date (00:00)     | {"t": "ge", "att": "_created", "val": "$TODAY"}     |
| -P10D         | Minus 10 days from NOW   | {"t": "ge", "att": "_created", "val": "-P10D"}      |
| P1M           | Plus 1 month             | {"t": "eq", "att": "_created", "val": "2020-01-01T00:00:00Z/P1M"} |
| date1/date2   | Date range               | {"t": "eq", "att": "_created", "val": "2020-01-01/2020-02-01"} |
| -P2Y/$NOW     | Last 2 years             | {"t": "eq", "att": "_created", "val": "-P2Y/$NOW"}  |
